# 60 · 反制机会的持续资格与结果封口

反制沿用现有 Window、作用域和普通规则函数；机会的持续资格与已封口结果分别处理。

## 反制机会

[contestCounter](../src/rules/cards/counter.ts)在开窗、逐席征询、实际用牌和结果封口处重查原机会：游戏未结束、原目标存活、原效果仍相关。原用牌者死亡不属于撤销已宣告效果的条件。

## 复用现有窗口能力

`counterOpening` 使用机会自身的纯 `available` 作为 Window.active。同窗持续检查与原来的征询/最终用牌资格共用条件；普通相关性闭包即使没有修改 World，也能收束本次开窗。不要求扩展作者给每个后续候选重复判断整个反制域。

结束开窗不回滚已经支付的费用、已宣告用牌或材料移动。只中止一个候选的 `ctx.abort` 仍是局部中止；只要原机会有效，其后候选及真实决斗继续运行。原来源或其他角色死亡也不会误伤存活目标的机会。

每次嵌套反制拥有独立生存期与 root，普通嵌套用牌也是独立流程。内层决斗令外层目标死亡时，内层仍可完成自己的反制与伤害，外层返回后停止自己的剩余候选。

## 结果与已发生事实分别保存

完成循环后、提交 counter.finished 前再次检查原机会。失效时 kind 为 unavailable；如果反制牌已经实际使用，by 仍保存其 CardUseRef，不能把真实支付和用牌身份删除。准备失败且未支付时 by 为 null，材料保留原位。

这项检查发生在结果封口之前。counterFinished 仍是已经提交的公共完成窗口：其中一个完成后效结束整局，不倒改刚刚封口的 unopposed，也不自动吞掉其他公共完成候选。没有为所有公共完成窗口套上待决资格。

## 验证入口

[反制边界场景](../tests/scenarios/counter-boundaries.test.ts)核对同窗与嵌套失效、已支付材料、真实 by、局部中止及公共完成后效，并检查牌守恒、处理区清理和事实重建。检查方法见[标准验收入口](53-standard-semantics.md#行为清单与检查)，当前运行与交付见 [STATUS](STATUS.md)。

# 41 · 模式行动序与事件主体

标准模式现在以当前活动回合角色为默认行动序起点；回合外退回事件主体，没有主体才使用首席。通用内核不导入回合规则。窗口、目标遍历、反制、救援和主公技询问共用同一政策入口，实际用牌者、响应者和受益者继续各自保留。

## 参考与问题

本地 [FreeKill 触发循环](../freekill/lua/core/trigger_event.lua) 从 `room.current` 开始遍历；本地 [noname 用牌流程](../noname/resources/app/noname/library/element/content.js) 以 `_status.currentPhase || player` 排序目标。它们帮助确认“谁正在行动”与“当前事件属于谁”需要分开，不意味着新内核复制其事件架构或已完成全包语义验收。

旧实现中，窗口有的显式从来源开始，有的从目标开始，无主体窗口使用首席；反制、救援和主公技又分别读取回合状态。用牌目标还单独按来源旋转。这些分支在“回合角色、用牌者、响应者相同”的常见局面里看不出区别，却不能构成统一的模式规则。

## 小型政策入口

[Room](../src/core/runtime/room.ts) 的 `RoomOptions.actionAnchor` 接收普通纯函数：

```ts
type ActionAnchor = (ctx: Context, subject: string | null) => string | null;
```

返回已知席位 ID，或明确返回 `null` 让内核回退。政策可以读取当前 World 和事件主体；不从历史或 UI 猜测参与者。未知席位、`undefined` 等非法结果在执行触发之前报错。函数在纯查询守卫内运行，不能提交状态或开启子操作；它不是脚本沙箱，也不限制普通内容代码的控制流。

[turnActionAnchor](../src/rules/turn/order.ts) 是标准模式政策。[RoleMatch](../src/app/offline/role-match.ts) 默认选择它，也可以通过 `actionAnchor` 传入其他政策。裸 `Room` 不自动成为三国杀身份模式；没有模式时继续遵守调用者的主体回退。

`activeTurn`、共享状态目标和回合来源校验移至独立的 [turn/state.ts](../src/rules/turn/state.ts)，避免排序政策依赖用牌、摸牌和完整回合执行器。核心只认识传入的函数，仍不认识活动回合字段。

## 显式覆盖、模式与回退

`WindowOptions` 的两个字段具有不同含义：

| 字段      | 含义                                                   |
| --------- | ------------------------------------------------------ |
| `subject` | 事件主体席位，提供给政策，并作为政策返回 null 时的回退 |
| `anchor`  | 特殊规则显式指定起点，覆盖模式；提供时不运行默认政策   |

优先级为：**显式 anchor → 模式政策 → subject → 首席**。主体和起点都必须是已知席位。普通领域操作只声明主体，不能用主体绕过模式。作者确实需要特殊顺序时，仍可显式覆盖，不增加特殊技能类型。

`ctx.actionOrder(subject?)` 在同一政策下返回冻结的完整席位序列；它是可用于纯查询的读取入口。序列包含死亡席位，调用者再依据实时存活、势力、禁令等条件筛选。距离计算与正常回合游标仍使用物理座次，不被窗口政策偷偷改写。

政策选择的是顺时针序列的起点，不提供任意座次重排。窗口的具名组优先级，以及同组无主系统规则先于玩家规则的既有契约保持独立。

## 真实回合与作用域

标准政策同时要求 World 中的回合 ID 属于当前 Context 的祖先作用域：

- 活动 b 回合中，即使 a 用牌、c 响应，默认起点仍是 b。
- 独立规则流程没有活动回合时，c 的响应完成窗口可以从 c 回退。
- 嵌套 d 回合使用 d；嵌套回合返回后恢复外层 b。
- 额外回合采用其真实拥有者，不继承正常轮转游标。
- 当前回合角色死亡不会删除席位或立刻把起点改成首席；其他存活角色从其后续座次参与。
- 孤立阶段不冒充回合；仅从事实重建得到的旧回合数据也不冒充当前执行。

这个检查没有尝试恢复挂起的协程，也不把一份 World 快照解释为正在运行的调用栈。

## 窗口与目标分别固定顺序

每个窗口在入口取一次政策快照。回调或嵌套结算可以影响后续新窗口，不能倒排本窗口剩余候选。`window.order` 诊断轨迹记录窗口、主体、实际起点和是否显式覆盖；它不是游戏状态事实。

每张牌在创建用牌计划时取得完整行动序，保存为 World 中的 `UseDeclaration.actionOrder`，并通过 `UsePlanView.actionOrder` 与 `UseSnapshot.actionOrder` 暴露。初始目标、后续追加/转移身份、四层目标时点和实际生效都使用这份序列。外层牌不会因子技能临时运行另一个回合而改变剩余目标的优先级。

新增目标仍只补齐未进入的时点；已经执行过的身份不回滚。较早座次的新目标可先于其他未处理目标，但不能重写已经发生的结算。嵌套回合创建的新牌取得自己的新序列。

反制、救援、护驾与激将的询问队列也使用 `ctx.actionOrder(...)`，不再各自读取一份回合政策。队列进入时取得顺序快照，每次参与前仍重查当前资格。起点变化只改变询问顺序，不把实际供牌者改写为主公，也不把响应改写为用牌。

## 验证与边界

[37 项行动序场景](../tests/scenarios/action-order.test.ts) 覆盖：

- 通用 Room 与模式隔离、主体输入、显式覆盖、政策纯查询、非法结果、入窗快照、参数快照、组顺序和两个 Room 隔离。
- 活动回合与回合外、嵌套回合正常/局部中止、真实额外回合调度、死亡起点、孤立阶段与旧事实数据。
- 不同回合/用牌/响应角色、真实鬼才、模式覆盖下的反制/救援/护驾/激将，以及实际参与者归属。
- 多目标四层遍历、较早身份追加、外层牌冻结顺序和嵌套回合新牌顺序，以及真实五谷的共享牌池分配；关键场景核对 World 事实重建。

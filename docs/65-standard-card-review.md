# 65 · 标准牌条件清单

更新：2026-10-18。本批继续 [64](64-standard-skills-review.md)，逐条核对余下 32 种标准＋EX 牌。默认仍为固定人类甲席、其他基础 AI；Android 构建与设备验收等桌面版完成后开展。

## 32 种牌的登记范围

[牌清单](../scripts/standard-card-review.mjs) 与 [技能清单](../scripts/standard-behavior-review.mjs) 合并后为 **72/72 对象、172 条条件、480 条去重断言、零待登记对象**。其中本批牌清单增加 69 条条件。条件由人工对照规则文本、实现和测试断言登记，检查器只核验登记内容，不按牌名推断覆盖率。

| -------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |

## 本批补测

[27 项标准牌场景](../tests/scenarios/standard-card-baseline.test.ts) 包括：

- 六种坐骑分别真实使用安装，验证修正方向、自己距离零、距离下限、材料排除、失效到期和卸下。
- 九把武器分别真实安装，验证实际范围、其他角色不借用、材料排除、失效到期和转移后的新归属。
- 丈八的使用/打出配方各验证恰好两张本人手牌，排除重复、数量错误、他人牌和装备；交出后旧选择失效。
- 八卦阵与仁王盾分别拒绝指定他人，真实安装到本人防具槽，转移后能力跟随实体。
- 闪电分别验证红桃、方块和梅花五不造成伤害，实体与原 UseId/牌面传给下一角色。
- 两种延时牌分别验证本人/他人目标、重复拒绝和不提前判定。
- 无中生有验证本人目标、真实摸二和材料善后，再分别验证一层/两层无懈的实际结论与独立材料善后。

最初 23 项中的五项失败来自夹具：两项把候选的 `kind` 误读为嵌套选择字段，三项误要求闪电传递后的处理区引用与最初使用相同。候选类型在外层，传递应保留原用牌身份与牌面，同时使用本次处理区引用。修正夹具后通过，再补两件防具安装场景，共 25 项。复核清单时发现无中生有原拟引用的两条无懈证据实际使用决斗，遂补本牌的两项直接断言，共 27 项；没有用别的锦囊测试替代此条件。

本批没有发现或修正规则玩法缺陷，没有修改内核、标准内容、基础 AI 或客户端运行代码。首次完整 1451 项运行期间仍在补无中生有两项，因此原报告另存 `standard-cards-full-before-direct-counter.json`；最终重新生成完整报告，不以旧报告支撑新测试。

## 完整目录检查

```sh
pnpm test
pnpm audit:standard:behavior --complete

# 含类型、Lint、文档、完整测试、严格目录检查和生产构建。
pnpm check
```

`pnpm check` 从本批起使用 `--complete`，防止遗漏登记对象时仍通过主检查。普通 `pnpm audit:standard:behavior` 仍可用于局部审阅，严格模式要求所有目录对象登记。当前严格模式通过；以后增加/移除项目标准目录时仍须明确更新基线与条件。

[检查器](../scripts/audit-standard-behavior.mjs) 继续验证规则文本一致、具名断言唯一且通过、完整报告时效。拆分后的两份人工清单都记录 SHA-256，并进入报告输入，不能只记录入口文件。常规检查不读取参考项目。时间戳与哈希服务于本地开发证据，不是外部签名或不可伪造的执行证明。

七组检查器探针包括五组 invalid 拒绝（缺失、重复、失败断言、过期报告、规则文本不符）、一组严格模式对遗漏一个对象退出 2，以及一组完整目录退出 0。清单遗漏与规则文本不符在独立子进程的模块缓存中构造，不编辑真实清单、源码或完整报告。即使完整目录通过，所有探针和真实报告中的 `fullOfflineVerified` 都仍为 false。

**catalogueComplete 只证明这份有限条件清单的目录登记完整。** 它不证明未列出的分支、任意内容组合、全部社区规则版本或完整离线产品验收。人工条件本身仍可在后续反例中修订，发现证据不符就补测或撤回登记。

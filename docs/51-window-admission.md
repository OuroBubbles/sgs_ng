# 51 · 同一窗口的新候选显式加入

更新：2026-10-18。本批接续 [有限次数](38-window-occurrences.md) 与 [来源登记](44-provider-lifecycle.md)，补齐窗口中新获得技能的显式加入。默认候选快照仍保持有限；只有作者明确请求才收集新候选。

## 具体窗口引用，不使用全局 currentEvent

ctx.windowOf(type) 返回当前 Context 最近的同类型祖先 WindowRef，窗口外返回 null。引用包含本次窗口 id、原 type 对象与 payload；同名嵌套窗口的引用不同。需要处理明确外层窗口时，可在进入子结算前捕获它。

```ts
const window = ctx.windowOf(damageReceived);
if (!window) return;

const change = await book.skills.grant(ctx, {
  owner: self.owner,
  skill: 'workshop:echo',
  source: { kind: 'effect', id: self.skill },
});

if (change.after) book.skills.include(ctx, window, [change.after.id]);
```

WindowRef 是执行侧引用，不是持久化快照，也不恢复挂起的协程。窗口关闭、正常中止、整局结束和故障都会清理登记；复制一个相同 id 的对象不能代替原引用。原窗口返回后，即使是同类型新窗口，也不能借旧引用操作新队列。

引用在初始候选与次数的纯查询中已经对应正确窗口；嵌套同名窗口不会意外返回外层 payload。纯查询只能读取引用，不能加入候选。

## 两层接口，普通作者代码

[Context.include](../src/core/runtime/room.ts) 接受 WindowRef、已在本 Room 挂接的 TriggerSource，以及可选的普通纯筛选函数；返回冻结的 WindowAdmission。核心不认识技能定义、装备或内容包。

[SkillBook.include](../src/rules/skills/skills.ts) 是规则层的便利入口。省略实例列表时，显式重新收集本目录的新候选；传入实例 ID 时，只选该窗口里的这些实际实例。它同样支持只有在特定窗口才提供绑定的 Provider，不解析触发 ID 字符串。新技能继续通过既有 on、invoke、pay、draw 和普通 await 表达效果。

调用者必须允许规则写入，属于目标窗口的实际后代 Context；等待子操作的父 Context、纯查询、只读投影、关闭上下文、其他局和不相关分支均不能改队列。子流程可以显式操作仍开放的外层祖先窗口，外层暂停期间只排队，不抢先运行新效果。

## 游标只前进，已有身份不重复

开窗时固定组与座次序，包含事件锚点和模式政策。每个组按该顺序经过无主项和各角色，和原有调度一致。

- 当前尚未完成的组/席位可以追加新候选；即使刚执行的旧项是最后一个，也不会丢失追加。
- 后续组/席位可入队；已经经过的组/席位返回 past，不倒转游标。后续组仍可包含此前角色。
- 同一来源已经进入本窗口的 Trigger.id 返回 known，包括零次数、已经执行或已经失效的身份。重复 include 不重读其次数，不复制剩余次数。
- 其他来源复用已有 ID 是作者错误，不能作为 known 静默吞掉。新选择 ID 也不能碰撞已存在的 occurrence ID，已经消费的 ID 同样保留。
- 来源卸载/同对象重新挂接不会复活旧候选；同一逻辑 ID 在当前窗口仍算 known。需要表示真正的新实例，应使用新的身份；技能失去后重新授予已有独立 SkillHandle.id，可明确加入。

新项不打断正在执行的普通回调。回调返回后，自动项继续先于需要排序的项；新旧可选项共用原 trigger-order 决策、独立 occurrence、执行前重查、当前资格、局部中止及有限次数处理。窗口中的新技能默认仍从下一窗口参与，授予本身不会隐式改变本次队列。

## 一批加入的边界

来源收集、筛选和新候选次数均在纯查询中执行。次数在候选首次入队时固定，不随之后后效重新计算；旧候选不会因为一次 include 而调用 times。零次数也占用本次身份。

整批先验证来源、身份、组、席位、次数与选择 ID；全部通过后才追加队列。作者异常或非法值不留下半批候选，也不预占本应未加入的 ID；已经发生的授予、费用或其他 World 事实不回滚。

返回值 state 为 open 或 stopped，added 为首次入队的候选 ID，skipped 区分 known/past。窗口 active 已为 false 时返回 stopped，不再收集新来源或读取新次数；原有窗口收束逻辑继续处理。stopped 与关闭引用不同，后者属于越界调用。

window.included 跟踪记录请求的因果路径、目标窗口 ID、加入与跳过结果；不把 Provider、函数或整个窗口引用写入事实。世界状态重建仍只依赖提交事实，不能从这条跟踪推断队列/协程已能恢复。

## 问道客：首次受伤就能使用新技能

[作者示例](../src/content/workshop/learning.ts) 中，拾慧是普通锁定触发：受到伤害后，若没有余响，先宣告，再通过 SkillBook.grant 获得余响，最后将返回实例显式加入捕获的受伤窗口。余响仍是普通可选触发：受到一次伤害后可摸一张牌，不按伤害点数重复。

首次伤害即可选择发动或拒绝余响。拒绝不失去已获得的技能；后续伤害自然收集余响，不重复学习或显式加入。失去/禁用、死亡、来源登记和费用资格仍由原有机制处理。

开局启用作者演武，选择问道客、两人、AI 关羽、护盾与转移牌组、种子 4；结束首个出牌阶段，完成弃牌后等待 AI 伤害。拾慧获得余响后，当前受伤结算直接出现余响询问。人类始终固定甲席，技能说明实时展示新获得的技能，没有设备交接。

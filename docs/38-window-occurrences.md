# 38 · 有限触发次数与组合语义审计

更新：2026-10-17。本批审计标准技能的多次发动与同一时点组合，修正遗计/枭姬的内部循环阻塞，以及不合资格身份被提前丢弃的问题。它是标准包系统审计的一部分，不代表二十五将和所有规则组合均已验收。默认人类甲席、其余基础 AI；Android 仍后置。

## 固定身份与次数，读取实时资格

[Trigger](../src/core/runtime/event.ts) 新增可选 times 函数，开窗时在纯查询中读取一次非负安全整数；省略时为一次，零次不进入队列。非法值和返回空值的已提供函数都会在执行任何效果前报作者错误，不默认为一次。次数函数不能提交状态、注册监听或消耗规则随机源。

每次结算有独立 TriggerOccurrence：id 在本局窗口因果路径内唯一，index 从一开始，total 在此窗口固定。相同来源在另一个窗口、嵌套同名窗口均产生不同身份。

窗口只处理入口时已登记的来源和固定次数。先按具名组，再按锚点座次；自动项优先于需要玩家选择顺序的项。同组同席位的效果读取最新资格，可以相互改变条件；一时不合资格的未处理身份不会仅因一次菜单预览被丢弃。

每个来源只提供最早合资格的一次进入当前菜单。若前面还有不合资格次数，直到玩家选定这个来源，才把该前缀正式记为跳过。选择另一个效果可能先使较早次数变为合法，菜单预览不会偷偷消费它。每次执行、拒绝或明确跳过都消费有限身份；没有可执行者时收束当前组/席位，过去的组、席位和已处理身份不回头。

例如 A 的第一次暂不合法、第二次合法，B 可以修改 A 的条件：当前可先选择 B，随后仍可执行 A 第一次；若先选择 A 第二次，则 A 第一次被明确跳过，之后不复活。角色不需要在同一个技能的多个相同次数之间无意义地选择。

新获得的技能/新注册来源仍从下一窗口参与。核心触发源注销、失去旧实例或死亡后的剩余次数继续重查资格，不借新实例复活；SkillBook 内部动态 Provider 卸载及同对象重新登记已补齐，见 [44](44-provider-lifecycle.md)。选择返回后再次检查来源；正常子流程中止消费当前一次并继续剩余队列，已提交事实不回滚。立即中止整局和未捕获故障仍沿用原诊断现场契约。

## 作者接口仍是普通代码

[on](../src/rules/skills/on.ts) 将 times 传入内核；回调为位置参数，when / effect 额外收到本次 occurrence（`at`）。times 在候选展开前固定次数，retain 为来源资格后备；它们只收到 `(ctx, event, self)`。

```ts
on(Damage.received, {
  id: 'per-point',
  times: (_ctx, hit) => hit.hpLoss,
  when: (_ctx, hit, self) => hit.input.to === self.owner,
  async effect(ctx, hit, self, _value, at) {
    // 一次独立发动；选择、费用、闭包、循环、子结算仍由普通代码表达。
    await handleOnePoint(ctx, hit, self, at);
  },
});
```

times 必须能读取当前事件负载，不能依赖尚未发生的后效；when 才是每次的实时条件。count 不会在效果后重新计算，也不会因为伤害后又失去体力、又移入装备而膨胀。需要每次关联不同项目时，可以从事件快照按 index 取值，或用独立触发闭包表达，不把闭包序列化为存档。

trigger-order 描述继续提供稳定选项 ID 和可读 labels，重复来源显示“技能 · 当前/总数”；另提供只含普通数据的 occurrences 元数据。window.candidate 跟踪记录来源、独立身份和 running/ineligible。队列与游标属于当前协程；状态重建不恢复挂起执行。

## 标准技能修正

| 技能/组合   | 当前行为与验收                                                                             |
| ----------- | ------------------------------------------------------------------------------------------ |
| 遗计        | 每点实际伤害各有一次身份，可在两次之间选择其他同一时点技能；每次内部的分批交牌仍用普通循环 |
| 枭姬        | 事件前后快照中每张离场装备各一次，次数不随之后移牌变化；拒绝一次不吞掉其他次数             |
| 遗计 + 刚烈 | 两点伤害可按“遗计一次 → 刚烈判定/反伤 → 遗计第二次”执行；刚烈本身仍按一次伤害触发一次      |
| 遗计 + 反馈 | 先给原本空手的伤害来源一张牌，再发动同窗口中刚变为合法的反馈                               |
| 枭姬 + 连营 | 可先拒绝枭姬第一次，再连营补牌，最后发动枭姬第二次；手牌变化后重新判断连营                 |
| 观星 + 洛神 | 两者明确为 choose，可由本人选择准备阶段先后，真实改变后续判定/牌堆                         |
| 英姿 + 裸衣 | 两者明确为 choose；零张阶段摸牌可先英姿变一张，再裸衣少摸这一张，不把裸衣提前永久丢弃      |

其他自愿发动的集智、铁骑、闭月也明确声明 choose；锁定修正与装备维护继续是自动项。这里没有添加随意填数值优先级的接口。洛神一次已接受发动后的连续判定仍是一次效果内的普通循环，不把每个 await 都拆成可被其他同一时点技能插入的步骤。

参考 [FreeKill 触发队列](../../freekill/lua/core/trigger_event.lua)、[遗计次数](../../freekill/packages/standard/pkg/skills/yiji.lua)、[枭姬](../../freekill/packages/standard/pkg/skills/xiaoji.lua)、[观星](../../freekill/packages/standard/pkg/skills/guanxing.lua)、[洛神](../../freekill/packages/standard/pkg/skills/luoshen.lua)。本实现固定窗口身份与次数，不照搬重新计算次数或全局数值优先级。

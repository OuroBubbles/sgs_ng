# 50 · 当前牌面、判定与宣告快照

更新：2026-10-18。本批接入红颜式牌面过滤，并以标准技能组合及作者演武验证。实体印刷牌面、当前角色的牌面与已宣告语义快照各有明确用途。

## 一次纯查询，不改写实体

[CardBook.face](../src/rules/cards/book.ts) 返回冻结的 PhysicalCardFace：id、name、suit、rank、color。World.card(id) 始终保留印刷牌面；查询不移牌、不登记技能，也不提交事实。

默认视角从当前区域派生：手牌/装备使用实际持有者，其他区域的 player 为 null。传入第三参数 judgmentPlayer 时，明确按该角色的判定计算，不把改判供牌者当作被判定者。

[cardQueries.cardFace](../src/rules/cards/face.ts) 沿用既有 modify。所有贡献读取相同的印刷 card、player 与 judgment 标记；返回 name/suit/rank/color 的部分修改，undefined 表示不贡献：

```ts
modify(cardQueries.cardFace, (_ctx, input, self) =>
  input.player === self.owner && input.card.suit === 'spade'
    ? { suit: 'heart' as const }
    : undefined,
);
```

不同字段合并，同值重复合并，冲突值明确报错；不按技能登记顺序静默覆盖。只有改变 suit 时，颜色按新花色派生；color 可以独立指定，保留此前的花色/颜色分离能力。非法名称、花色、点数、颜色与拼错字段会产生作者诊断。

贡献不按修改后的结果循环重跑。确需组合政策时由普通作者函数显式决定返回值；递归读取同一牌/判定视角有明确错误，不以堆栈溢出终止。不同实体的纯组合查询仍可使用，错误退出后也不残留求值标记。

## 实体、转换与已有宣告

physicalCard 与实体用牌/打出通过当前牌面构建；过滤不是额外支付的转换配方，实体来源仍为 source:null。ViewAs.materials 现在接收第三参数 book，可以查询当前材料；武圣、急救、倾国、奇袭、国色、龙胆均已接入。

单材料转换默认继承当前材料的花色、点数与独立颜色；多材料仍按同色规则派生颜色，显式 make 的字段优先。修正“红色黑桃材料转换后又由花色推成黑色”的缺口。显式 generated 牌面与已提供的供牌快照仍按调用者给出的字段保留，不再从已经离手的材料反推。

使用/打出在最终验证与支付时确定语义牌，后续失去过滤技能、材料离手、来源死亡都不改写这张已宣告牌。距离、禁令、次数、目标和处理区沿用已有管线。名称过滤可供普通牌与转换查询；转换装备的持久身份仍受 [装备协议](18-equipment-queries.md) 的既有边界限制，本批没有补齐任意转换装备。

## 判定以被判定者为主体，封口以后不重算

当前调用为 judge(ctx, book, input)，显式使用本局目录；未保留会静默跳过过滤的旧入口。洛神、铁骑、刚烈、八卦阵、乐不思蜀与闪电，以及直接判定场景均已更新。洛神/铁骑按现有工厂模式接收 book，八卦阵通过装备能力工厂接收 book。

公开/改判记录保存当时牌面；封口前 Judgment.card 按最新技能状态重新查询同一实体和被判定者。失去/获得过滤可改变最终匹配，改判后的实体也使用同一规则。封口时先确定牌面和 match，再开放 judgmentFinished 和 onResult；此后技能变化或牌被获得，不改变结果快照。

例如带映绯的 a 用自己的黑桃牌为 b 鬼才：a 的实际打出为红桃，但 b 没有过滤时，最终判定为黑桃。鬼才候选继续验证实际供牌者的打出禁令，不能用判定视角绕过它。

反间也改为在交牌及其后效完成后比较当前花色；黑桃交给带映绯的目标后，猜红桃不受伤。

## UI 与基础 AI 共用查询，历史不借用当前状态

[Room.inspect](../src/core/runtime/room.ts) 提供同步只读上下文，供投影使用同一规则查询。它不启动流程、不消耗因果编号或随机源、不生成事实；返回/异常后上下文立即关闭。运行中等待决策或结束后都可读取，禁止提交、子流程、等待、监听、资源登记和通过捕获的 Room 写入。它没有提供新的状态所有者或恢复牌局调用栈。

修正 Room.run 在纯查询中先改 status 才拒绝写入的问题；现在拒绝发生在修改运行状态之前。

手牌、公开装备与 AI 有权观察的牌使用当前牌面；其他角色的隐藏手牌仍不投影。桌面处理中使用 use/response/judgment 的既有快照。仅包含实体 ID 的移动日志继续按印刷牌识别，不能从当前持有者的过滤改写过去；完整移动知识与记忆语义仍在后续范围。

鬼才请求附带仅本人合法候选在被判定者视角下的 alternatives。基础 AI 用该数据评估改判，不能把自己的黑色手牌误认为一定能令对方判黑；颜色判断也优先使用显式 color。

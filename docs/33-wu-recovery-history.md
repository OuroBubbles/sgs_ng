# 33 · 回复草案、活动查询与吴将

更新：2026-10-17。本批接入孙权（制衡、救援）、吕蒙（克己）、陆逊（谦逊、连营），本批时共十八名可选标准武将，后续二十一武将见 [34](34-target-declarations-tacticians.md)。默认仍是人类甲席、其余基础 AI；完整离线内容继续推进，Android 构建后置。

## 回复的尝试量与实际量

[recover](../src/rules/combat/recover.ts) 新增 `recovering` 窗口。`RecoveryDraft.input` 是冻结的原请求；`amount` 是当前尝试回复量，可用 `adjust` / `setAmount` 修改并记录原因。数值必须为非负安全整数，修改仅在该窗口有效，纯查询与封口后不能修改。

窗口结束后重新读取目标的存活、当前体力、上限与终局状态，再计算实际回复。结果区分 `input.amount`、`attemptedAmount`、实际 `amount`，并记录有序 `edits`。窗口内其他结算改变了体力或杀死目标，不会以旧体力覆盖当前状态。只有实际回复大于零才提交 `hp.recovered` 并开放 `recovered` 后窗口。

救援是普通回复前技能：当前其他吴角色使用的语义牌为桃时，尝试回复量加一，再受上限裁剪。急救等转换产生的桃同样有效；自己用桃、非吴来源和普通技能回复不满足条件。身份模式只向主公初始授予此技能，不在技能内核硬编码身份。

将尝试量设为零只是一次数值修改，不等于禁止后续所有修改。本批没有加入回复转移、不可覆盖的禁止或完整回复替代系统。

## 可查询的真实用牌活动

[cardActivities(facts, withinScope?)](../src/rules/cards/activity.ts) 接收完整、有序的事实列表（如 ctx.history.facts()），返回按序的使用/打出、实际角色、语义牌和作用域路径；后续 [53](53-standard-semantics.md) 补充宣告当时的 turnId 与实际 phase：

- 普通使用读取 `card.used`。
- 普通响应与供牌读取 `card.responded`，归属实际供牌者。
- 鬼才式打出改判读取 `judgment.replaced` 中同次提交的 `response` 和 `invocation`，不再伪造另一笔打出事实。

普通移动不被视为使用或打出。此接口读取规则库的领域事实，而非中文日志或技能临时计数；技能在活动发生后才获得，仍能查询此前发生的事实。

克己在弃牌开始前，按每条活动的 turnId 和实际 phase 选择本回合本人出牌阶段中，本人使用/打出的语义杀。因果后代不等于本回合活动：嵌套其他回合、内层非出牌阶段、开始前/结束后均不混入，详见 [53](53-standard-semantics.md)。转换杀、普通响应、供牌和改判均可计入；他人使用、其他阶段、前一回合及普通移牌不会误计。重复出牌阶段全部纳入本回合。没有活动回合的独立弃牌阶段没有本回合出牌记录。

接受克己时，零费用宣告与 `phase.skipChange` 同次提交，支付后效已经能看到跳过意图。取消不支付；跳过仍遵守统一阶段流程，不执行弃牌阶段体或开始/结束窗口。

## 制衡、谦逊与连营

[wu.ts](../src/content/standard/wu.ts) 保持普通技能代码：

- 制衡复用联合选择与 `payDiscard`，手牌/装备一次支付，阶段限一次；后效结束后按此次实际费用数量摸牌。失去技能不撤销已宣告效果，来源死亡或终局则停止。采用标准版，不附加界版的弃光手牌奖励。
- 谦逊贡献纯目标禁令，禁止顺手牵羊和乐不思蜀；宣告与效果前重查沿用既有目标管线，技能失效后不再贡献。
- 连营依据批量移动的前后牌区快照识别最后手牌离开，再检查当前仍空手。一次移出多张只询问一次；部分手牌、单独装备和死亡埋葬不产生错误机会。重新得牌再失去是新的机会。

连营接受后再获得手牌或失去技能，不撤销这次已宣告摸牌；本人死亡或终局停止。它可以嵌在用牌、弃牌费用中，原用牌的语义和材料仍按各自处理区继续，不因摸到新牌而重建或追回。

## 验证与边界

[35 项新场景](../tests/scenarios/wu-generals.test.ts) 覆盖回复草案、封口/纯查询、零回复/死亡/当前体力裁剪、真实救援和急救转换；制衡取消/权限/装备/失去与死亡；克己的使用、普通打出、改判、先行动后获技能、重复阶段与跨回合；谦逊目标资格及连营的批量、拒绝、重新得失、死亡和用牌内嵌套。

八人标准＋EX 局通过基础 AI 的正式决策到达身份胜负，并严格检查实际发动制衡。[浏览器](../tests/browser/client.spec.ts) 与 Windows 原生证据见 [STATUS](STATUS.md)，不以桌面触屏模拟代替 Android 真机验收。

截图检查另修正横屏记录抽屉：压缩标题、关闭按钮与页脚占用，保留可滚动的正文空间；加入首条正文完整处于视口内的检查。回合交接的暂时空阶段显示「回合衔接」，不再误报「尚未开局」。

本批没有完成其余标准武将、通用分组/排序选择、完整信息记忆、内容包或高级 AI。活动查询和回复草案作为规则标准库的小接口，不引入技能 DSL 或通用管理器。

# 61 · 目标身份与效果启动的持续资格

目标调度复用 Window.active，领域代码决定目标身份与持续资格。

## 目标窗口

[四层目标调度](36-target-stages.md)在层间及同一窗口的候选边界重查资格。取消、移除、转移、死亡、终局或动态禁止会收束旧 EffectId 的待决窗口。

## 两种待决资格

[CardBook](../src/rules/cards/book.ts) 给五个窗口传入各自的纯 active 条件：

| 窗口范围                       | 同窗持续条件                                             |
| ------------------------------ | -------------------------------------------------------- |
| 指定前、确认前、指定后、确认后 | 本身份仍为 targeting，目标存活、游戏未结束、目标未被禁止 |
| effectStarting 的全部组        | 本身份仍为 ready，满足上述实时条件及该牌 canResolve      |

取消、移除和转移使旧身份离开待决状态。转移产生新 EffectId，按原四层调度补齐时点；停止旧窗口不等于停止整张用牌。其他有效目标照常结算。来源死亡也不被一律视为目标失效，已宣告杀仍可对存活目标结算。

canResolve 只属于实际效果。满体力桃园目标仍可进入四层声明，在此期间受伤后正常回复；不能为了统一检查而提前过滤它。效果启动中，桃园目标被先行治满，或顺手/拆桥的目标失去最后一张可操作牌、来源死亡，才按各牌自己的 canResolve 停止本窗后续候选。

active 由普通回调决定，不新增 World 状态。窗口执行器继续负责候选顺序、次数、纯查询及停止，领域代码仍负责目标身份和牌规则。

## 已发生的事与正在执行的函数

停止窗口不会回滚先前提交的费用、转移宣告和实际用牌，也不打断正在运行的候选函数。作者在一个候选内部 await 了嵌套流程，仍须在后续支付或操作处按真实条件重查；本次修复只负责窗口的候选边界，不承诺任意函数位置自动挂起或回退。

`ctx.abort` 只中止当前候选时，不自动取消目标；资格仍有效便继续下一候选。内外用牌各有独立窗口，内层杀令外层目标死亡时，内层自己的目标仍可完成伤害，返回后才收束外层。

effectFinished、useFinished 属于已经提交的公共完成后效，保持原语义。取消身份仍记录 card.effect，并进入 effectFinished；某个完成后效结束整局，不倒改此前封口结果，也不自动吞掉其他完成候选。需要观察取消结果的扩展应使用完成窗口，而非期待 effectStarting 的 after 组在失效后继续运行。

整次用牌的 useDeclared/targetsConfirming 不套用某一个目标的 active；它们仍可显式追加目标。原分层、冻结顺序、动态追加及处理区善后保持原契约。

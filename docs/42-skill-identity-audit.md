# 42 · 技能身份、次数与伤害归属审计

更新：2026-10-18。本批继续标准包语义审计：修正结姻重新授予后的次数刷新、技能变更事件主体和裸衣决斗归属，并增加二十五名标准武将的整局路径验证。完整离线版仍按 [路线](11-offline-roadmap.md) 推进，默认人类甲席、其余基础 AI；Android 继续后置。

## 技能实例与阶段计数具有不同身份

`SkillHandle.id` 标识本次拥有的技能实例。最后一个授予来源失去后，再次获得会产生新 ID；旧菜单、转换引用和已收集的旧候选不能借新实例复活。支付宣告中的 `PaymentReceipt.instance` 也必须继续记录实际支付的旧实例。

阶段次数是另一项规则状态。标准结姻、制衡、青囊、反间和离间均规定每个出牌阶段一次，因此以 `self.skill` 作为 [UsageLimit.source](../src/rules/costs/pay.ts)，由角色、计数 key 和明确的 Phase Lifetime 共同确定额度。结姻此前使用 `self.id`，导致支付后失去并重新获得时可以再次发动；现在与其他四个技能统一。

没有添加全局的自动计次规则，也没有改写作者 API。扩展若确实需要每个实例独立计数，仍可明确选择实例 ID；多个主动分支可以明确共享或分开 key。普通函数继续负责选择、支付与后效。

这几种变化都不能刷新同一标准阶段的次数：

- 支付后移除最后一个授予，再重新获得新实例。
- 暂停唯一授予，再启用原实例。
- 增加另一个授予，再移除原授予；共享实例继续存在。

已付费用、次数和宣告保持原样，已发动效果继续按文本执行。下一阶段有新额度；嵌套的同角色出牌阶段也有自己的额度，但返回外层后不会清掉外层已经使用的次数。

[skill-identity.test.ts](../tests/scenarios/skill-identity.test.ts) 用五个真实主动技能分别覆盖这三种来源变化和嵌套阶段，检查旧实例归属、菜单与直接提交的最终校验、后续真实摸牌/回复/交牌/决斗，以及事实重建。材料和替代目标仍足够，避免把“没牌/没目标”误判为次数限制生效。仁德的阶段累计仍使用此前已有的稳定技能来源，继续由 [benevolence.test.ts](../tests/scenarios/benevolence.test.ts) 覆盖重新授予不刷新门槛。

## 技能变更保留事件主体

[SkillBook](../src/rules/skills/skills.ts) 的授予、启停和撤销，继续原子提交带有 before/after 的 `SkillChange`。`skillsChanged` 现在明确声明拥有者为 subject：回合外从该角色开始，真实活动回合内仍优先 [模式行动序](41-action-order.md)，不把事件主体误写成显式起点覆盖。

这不扩展窗口候选发现，也不把已经失去的技能视为当前有效。通用来源遗留、新来源显式补入和独立效果的完整协议仍在后续范围内。

## 裸衣区分牌使用者与伤害来源

本地参考在此处存在差异：

- [FreeKill 标准裸衣](../../freekill/packages/standard/pkg/skills/luoyi.lua) 要求 `by_user`；[伤害流程](../../freekill/ltk/server/events/hp.lua) 从牌效果的使用者与实际伤害来源是否相同建立这个条件。
- [FreeKill 决斗](../../freekill/packages/standard_cards/pkg/skills/duel.lua) 保留实际胜方为伤害来源。
- [noname 标准技能](../../noname/resources/app/character/standard/skill.js) 的裸衣分支按伤害来源、牌名及非连环判断，因此允许作为决斗目标打回时受益。

本项目标准包与技能说明统一采用上述 FreeKill 条件：`DamageInput.from` 和 `EffectRef.actor` 都是本人，且牌为杀或决斗，才加一点伤害。不会为了不触发裸衣，把实际伤害来源改写为决斗使用者；响应与用牌事实也仍各自保留。

已发动的裸衣回合效果继续从状态通过 Provider 派生，不依赖原技能继续持有；本人使用实体决斗或零材料 generated 决斗均正常增伤。[wei-generals.test.ts](../tests/scenarios/wei-generals.test.ts) 同时验证正例和作为目标打回的反例，核对实际伤害、来源、牌使用者、修改记录、处理区清理和事实重建。

此前 [29](29-wei-judgment-effects.md) 中允许决斗目标受益的描述已同步修正。没有据此引入通用伤害标签体系；连环、转移和其他未来伤害规则仍需各自设计、验证。

## 二十五种真实身份局

[standard-games.test.ts](../tests/scenarios/standard-games.test.ts) 按标准目录逐将构建四人局：该武将位于甲席，其他三席使用目录的不同偏移组合，种子为 `42 + index * 17`，标准＋EX 108 张牌。没有重排起手、注入 World 或直接写胜负。测试中四席都由现有信息受限基础决策器驱动；产品默认的一名人类主控边界保持原样。

每局通过 [playMatch](../tests/fixtures/match.ts) 在测试清理前统一检查终局不变量；场景单独核对武将身份、108 张牌组及实际苦肉发动：

- 真实准备、回合、出牌/响应/技能等决策均合法接纳，不出现未知必选决策或运行时故障，最终产生且仅产生一次真实胜负。
- 等待整局 Promise 完成后，没有待选决策、活动回合/阶段、悬留用牌宣告、处理区或私有临时牌池。
- 全部 108 张实体牌仍各自在唯一位置，提交事实重建结果等于当前 World。

`.artifacts/validation/standard-games.json` 由测试实际生成，记录每局武将/种子/阵容、决策数、回合数、胜负，以及确实产生过的主动/触发宣告和用牌集合；只有全部二十五局通过时 complete 才为 true。每局有决策数与测试时间上界，不把未结束的对局当作成功。

武将进入并完成一局不等于其每个技能、锁定修正、转换分支和所有牌型组合都已执行；`skill.invoked` 集合尤其不能替代查询修正或转换的覆盖证据。完整分支审计继续依赖具名场景，不能用这些整局结果宣布全包验收完成。

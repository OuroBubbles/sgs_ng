# 11 · 项目方向与收敛计划

2026-10-29。终极目标是以简洁语义、优秀实现与玩家体验持续逼近 SoTA。当前按个人开发、AI 辅助组织源码，不再以开放创作者生态为开发前提。内置内容直接定义和组合，不强制分发包、依赖清单与版本元数据；未来扩展保留接缝，不让其部署生命周期成为日常内容开发的负担。底层不限制复杂技能的普通代码表达，不为局部最优或重构成本保留包袱。

当前优先级是代码级收敛：普通内容装配已统一，主动与转换技能改用具名输入，Context 仍显式传递。转换各阶段可直接读取本局目录与实际用途，构牌参数不再依赖位置占位；触发和查询继续保留各自清楚的领域参数。客户端安装与持久内容库、包格式、专用编译器及模块安装实现均已移除；日常单机和主持直接装配源码。选择、支付、查询与嵌套结算的领域约束保持，每步用真实内容和已有语义反例验证，不为形式统一制造新的万能对象或 DSL。

平台路线保留为历史交付顺序：①离线桌面、UI 与 AI 托管；②桌面联机；③Android 与双端联机。当前代码收敛不等待外部设备，原生包在语义与装配稳定后再同步；跨机器、真机和双端互通的旧验收缺口不计为通过。Spine 仍后置。

离线阶段的规则、作者、桌面游玩与长局释放证据已补齐，具体范围见 STATUS。桌面阶段已接入随包主持端与界面创建/加入，离线基线继续作为回归范围。

本文件只维护目标、取舍和下一步；验证结果只在 [STATUS](STATUS.md) 维护。历史编号文档提供专题依据，其中的“下一步”不再自动成为任务。

## 本次整体判断

技术选型和主干分层可以保留。World / Flow / Window / Decision / Fact 有明确职责，规则与表现已分开，普通 TypeScript、共享模块身份和统一合法性入口符合初衷。保留概念不等于保留旧接口：流程已从逐层返回中止改为默认传播，规则函数直接返回领域值，恢复边界显式声明。

偏移主要发生在增量开发方式：局部缺陷被逐个修复，接口隐含规则、历史说明和验证成本却没有同步收敛。完整检查通过只能说明已有断言成立，无法证明整个系统已经简洁。

## 现在收敛什么

- 暂停新增武将、牌组与测试框架，保留固定甲席＋基础 AI。FreeKill 组件与音频已经接入；桌面主持复用同一规则与逐席投影，Android 同步已有表现层，资源声明、公开投影和播放保持分离。
- README 只负责入口，STATUS 只负责当前事实，本文件只负责方向。修复说明回到对应契约；不再每批新建编号文档、复制多份进度或累积独立记忆。
- 测试优先保护独立的领域结果和已发现的回归；整局冒烟服务于装配与结束条件。合并前列明旧断言由谁继续保护，不通过跳过、放宽超时或降低标准清单换取更快检查。
- 读取当前源码和上述入口解决当前问题，历史记录按需查证，不让旧计划支配新工作。

## 离线阶段已收敛的边界

发动前的材料与目标统一接入已有 JointSelection，同一个出牌请求一次提交，作者契约见 [12](12-skills-selection-costs.md)。支付和后效的差异仍由普通控制流表达：制衡付费后摸牌，克己将阶段跳过与宣告同次提交，代受在支付后效前确定转移；结算中产生的新选择保留各自时点。

已收敛整局驱动、独立效果字段及流程传播语义，并在既有 immutable 函数中共享已验证的冻结子图，具体契约见 [04](04-resolution.md)。查询止写和只读类型之后，将支付的同步提交/宣告与异步后效分清，复用既有 Flow 故障捕获；没有增加运行核 API。作者入口 [05](05-authoring.md) 已替换过时示意，并通过原样代码的编译与真实结算验证。验证结果只维护在 STATUS，不自动追加框架。

已覆盖的边界：

1. 技能、响应、支付等普通调用无需逐层检查 aborted 或 unwrap；领域上的拒绝、未支付、被防止仍作为普通返回值。
2. 触发调度和单目标结算可明确隔离局部中止，后续候选/目标仍结算；阶段结果保留其领域语义。
3. 处理区、生存期及回合先善后再交回中止，事实不回滚；快照共享保持旧状态与事实不可变，旧对局可释放。Room 关闭和代码故障仍不能局部恢复。
4. 替换旧路径并删除重复传播，不保留兼容双轨；沿用现有边界与整局测试，仅补缺失的独立反例。文档原位修正。

每完成一个有边界的改动，就重新检查整体成本；不把“继续工作”解释为无限增加范围。离线桌面版的验收包括规则准确、作者可用、桌面可玩和长局稳定，不能由数量指标代替。

已验证的边界由运行核或领域操作负责：故障止写、资源注销、冻结快照与支付最终校验；作者用普通代码描述领域差异。后续检查继续以真实规则和扩展路径为依据，不把每次发现的问题变成永久追加的作者模板。

## 离线基线的收官判据

离线阶段的范围固定为现有标准＋EX、身份模式、固定甲席与基础 AI，以及普通 TypeScript 内容的组合和游玩。已有演武内容继续用于冲击机制边界，不以增加内容数量作为收官条件。

| 方面     | 可以据以结束本阶段审查的证据                                                               |
| -------- | ------------------------------------------------------------------------------------------ |
| 规则准确 | 选定文本的独立条件通过，真实整局到胜负；牌守恒、临时资源善后与事实重建一致                 |
| 作者可用 | 直接 import SDK 与普通源码；示例可编译，跨模块身份、资源与技能通过实际客户端结算           |
| 桌面可玩 | 当前 Windows Release 从开局到胜负；本人操作、其余 AI、取消和暂停有效，进程重启后可重新游玩 |
| 长局稳定 | 真实长局记录规模与驻留成本，结束和重复开关对局后可释放；说明测量环境，不外推移动端性能     |

四方面的判断与证据只记入 STATUS。审查结论针对上述范围，不承诺任意未来技能或任意设备；后续只有具体规则反例、实际作者障碍或测量瓶颈才重新打开对应设计问题。检查脚本的保守标记本身不产生新需求。

Android 复用已有原生壳与生命周期接口，核对当前源码的离线运行、前后台保持与进程重启。内容安装、系统选择器导入与数据库恢复已退出功能范围。模拟器只证明所记录环境中的行为；真机触控、系统栏、帧时间/内存与 16 KB 设备运行仍须独立验收。候选包与旧验收包分开保存，未完成的平台验收不因一次模拟器通过而关闭。

离线桌面 v0.1 的已验收范围保留，后续只由实际规则反例、作者障碍与体验问题重新打开设计。

## 桌面联机的下一步

Windows 客户端已可创建、关闭随包主持端，并给出可连接地址与可读的加入结果；普通玩家的主持流程不依赖源码目录中的开发命令。创建者配置复用原有对局装配，开放总席位、玩家人数、所选内容的牌组、阵容与种子；准备页展示实际配置。自定义内容使用同一源码装配，加入者只接收资源与视图。继续复用现有规则实例、逐席投影和统一选择校验，不向原生壳迁移规则。

真实跨机器创建、加入与整局仍须独立验收；设备不可用时推进可独立完成的部分。准备大厅已将玩家选将与实际对局分开，同房间可连续开局；重连继续原席位及实际挂起请求，不让草稿侵入 World，也不以重建事实恢复挂起协程。普通内容、资源传递与重连的验证范围见 STATUS。外部内容加载只保留源码接口，不预建远端安装或通用同步框架。不把等待设备变成反复重审离线基线。

同机双客户端回归保留，真实跨机器运行单独验收，不将本机回环结果当作跨机器证明。阶段与实现结果仍分别维护在本文件和 STATUS。

Spine、完整录像与任意时点续局仍后置；旧 P0 的骨骼压力场景不重新成为当前离线规则基线的前置条件。不为私有项目另加发布市场、签名分发或兼容旧包的门槛。

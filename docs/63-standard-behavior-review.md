## 从一条条件追到一个实际断言

[人工清单](../scripts/standard-behavior-review.mjs) 逐项保存项目采用的规则文本、条件说明、测试文件和完整测试名称。每条条件先对照实现与断言核对，再登记；检查器不会按技能名自动挑选“看起来相关”的测试。

首批为 15 个技能对象列出 49 条条件，对应 100 条去重后的通过断言：

| 组   | 对象                                     | 核对范围                                                                 |
| ---- | ---------------------------------------- | ------------------------------------------------------------------------ |
| 转换 | 武圣、龙胆、奇袭、倾国、国色、急救       | 数量、本人持有、手牌/装备范围、当前牌面、使用/打出用途及各自真实用牌路径 |
| 主动 | 苦肉、结姻、仁德、青囊、制衡、反间、离间 | 支付/取消、阶段次数或累计、来源变更、真实目标/回复/伤害和已宣告后续      |
| 目标 | 流离                                     | 弃牌与转移原子提交、弃装备后范围、新身份和旧窗口收束                     |
| 查询 | 咆哮                                     | 解除杀额度仍保留距离、目标和完整闪响应，失去技能恢复已累计上限           |

这是所列条件的证据绑定，不是 15 个技能的任意组合/所有可能分支覆盖率。40 个技能与 32 种牌形成 72 个对象的明确目录；当时其余 25 个技能和全部 32 种牌，共 57 个对象尚未逐条登记。完整待审 ID/名称由报告列出，不能用一次整局或文件存在补成已审。

核对中补了 [17 项标准配方场景](../tests/scenarios/standard-authoring-baseline.test.ts)：七个配方分别验证数量/牌面/归属/用途和装备区域，共 14 项；再实际授予武圣和咆哮，分别验证阶段额度、距离/本人目标与完整使用闪；最后验证急救回合外的规则使用可以真实自疗。这些测试补齐证据，不是本批发现的新玩法缺陷。

尤其不能用龙胆的额度测试替代武圣，也不能用未授予咆哮的场景证明咆哮保留距离。相同的基础管线有共同机制证明，技能专属声明仍须有对应条件与断言。

## 检查命令

```sh
pnpm test
pnpm audit:standard:behavior

# 要求整个 72 对象目录均登记；本批当时预期以退出码 2 拒绝 57 项未审内容。
pnpm audit:standard:behavior --complete
```

[检查器](../scripts/audit-standard-behavior.mjs) 核对规则文本是否仍与人工清单一致、具名断言是否唯一且通过、当前规则/相关测试文件是否晚于报告开始时间。报告记录当前输入 SHA-256、完整单元报告哈希、人工清单哈希、条件与去重断言，以及所有待审对象。时间戳检查是本地开发中的过期报告防护，哈希用于记录本次输入；它不提供外部签名或不可伪造的执行证明。

规则文本改变要重新审阅条件；缺失、同名歧义、失败或过期输入产生 invalid 报告并失败，不保留旧绿色结果。普通模式只检查已登记范围，并明确输出 partial/待审数；`--complete` 还要求全目录登记。即使未来 catalogueComplete 为 true，fullOfflineVerified 仍不会自动变成 true：平台、客户端、内容组合及未列出的契约仍要单独验收。

`pnpm check` 在完整测试后执行普通模式，持续保护已登记条件，不把它当作完整桌面验收门禁。[自有目录解析](../scripts/standard-catalogue.mjs) 从原参考清单工具中提取，共享同一份 25 将/40 技能/32 牌识别。普通行为检查只读项目代码与测试报告，无需 freekill/noname 或旧生成清单；显式 `pnpm audit:standard` 仍可生成原两份参考文本和 102 个输入哈希，仍为 behaviorVerified=false。

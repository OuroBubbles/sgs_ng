# 32 · 交牌累计、供牌使用与回合外救援

更新：2026-10-17。本批接入刘备（仁德、激将）、华佗（青囊、急救），本批时共十五名可选标准武将，后续十八武将见 [33](33-wu-recovery-history.md)。继续优先离线规则与作者体验；Demo 保持人类甲席和基础 AI，Android 构建等桌面完成后开展。

## 仁德与青囊：普通主动函数

[benevolence.ts](../src/content/standard/benevolence.ts) 直接组合联合选择、支付、状态和回复。仁德一次交给一人，可多次分配；只选本人手牌，交牌不受弃置禁令约束。移牌、技能宣告与阶段累计同次提交，移动后效不会看到尚未更新的累计。

首次累计跨过两张时才回复一次；满体力跨过门槛也不会在以后受伤时补发。累计以角色、技能和实际阶段生存期定位，失去并重获技能不重置；重复出牌阶段各有独立门槛。已交牌后目标死亡，牌照常埋葬，不撤销交牌。

青囊使用 `payDiscard`，仅一张可弃置手牌、一名受伤角色，可选自己。费用与阶段一次限制同次提交，取消不占次数；非终局时，成功宣告后失去技能或来源死亡不撤销对仍存活目标的治疗。实际回复仍经过统一回复规则，不能超过体力上限，终局停止后续效果。

## 供牌与使用分开

[withCardSupply](../src/rules/cards/supply.ts) 询问实际供牌者，以其权限构建并打出牌，材料进入独立处理区。回调在该处理区存活期间运行，后续用牌可以接走材料；未接走的余牌在正常完成或子流程中止后善后。不能将已经关闭的供牌句柄用于新流程。

供牌复用 `card-response` 决策、转换配方、支付和 `responseFinished`。`ResponseSubject` 新增 `supply` 用途，记录请求身份、受益者和原因，不伪造一个尚未产生的用牌效果。打出完成归实际供牌者一次。

结果区分未提供、放弃、已经供牌但失效和正常完成。供牌已经支付后，若材料不完整、供牌者或受益者死亡、原请求失效，不再继续向下一人收费；已支付的打出不回滚。零材料供牌也必须处于真实的供牌生存期中。

## 激将与转换的异步用牌

`ViewAs.use` 允许在初次用牌校验通过后，以普通异步代码询问供牌等准备。激将先确认刘备的目标、距离和次数，再依行动顺序询问当前存活的蜀角色；不预先读取对方手牌。实际牌收到后，调用普通 `book.use`，重新检查其真实牌面、目标、距离、禁令和刘备的次数。

生成牌可携带 `origin: { actor, card }`，保留实际供牌者及其完整语义牌快照，包括武圣、龙胆或丈八等转换来源。刘备的使用与供牌者的打出各有独立事实；材料没有先冒充刘备的手牌，也不会丢失为一张无来源的普通杀。

没有蜀角色供牌时，不消耗杀次数，本阶段不能再次主动以激将使用杀。打出请求仍走既有 `ResponseOpportunity.delegate`，仅收窄为杀；失败后本人仍能普通响应。此失败也会限制当前阶段后续的主动激将。阶段到期自动清理限制。身份模式仍只向主公初始授予激将；可信自定义模式可显式授予。

`ViewAs.use` 是可信内容代码入口，不是事务自动回滚或通用技能模板。激将明确使用常规用牌管线取得最终结果，其他作者代码也应保持各领域操作的语义。

## 当前阶段与急救

[currentPhase(ctx)](../src/rules/turn/turn.ts) 返回同一 World、当前祖先路径内仍存活的最内层阶段句柄。嵌套阶段结束或中止后恢复外层，阶段外返回空；可在纯候选查询中读取。它是运行期句柄，不能由事实重建正在暂停的协程。可序列化的 `activePhase` 仍由 World 持有。

急救依据 `activeTurn` 的真实拥有者判断回合外，包括额外回合。只允许红色手牌或装备作为桃**使用**，不能打出。救援沿用 `askUse` 和普通桃的目标、禁令、材料支付、回复及濒死后续；本人回合不能以急救救人。没有活动回合的独立规则流程按回合外处理，不从独立阶段的名字猜测回合归属。

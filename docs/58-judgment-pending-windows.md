# 58 · 判定待决窗口持续资格

2026-10-18。标准与演武内容版本 `0.1.16`；渡口仍为 `0.1.1`，精确依赖 `standard@0.1.16`。应用壳仍为 `0.1.0`。默认人类固定甲席，其他角色基础 AI，Android 继续等桌面完成后开展。

## 问题与边界

`judge` 原来只在打开 `judgmentRevealed`、`judgmentRetrial` 前，以及计算匹配结果前检查判定者是否存活、整局是否结束。候选执行期间发生死亡或终局时，结果虽然已经会变成 `unavailable`，同一个窗口中的后续候选仍可能执行。例如，第一个翻牌后效杀死判定者，第二个普通作者后效仍据此给另一角色发牌。结果最终不可用不能撤销这次错误的额外执行。

标准鬼才自身已有判定者存活与终局检查，但普通扩展不能依赖每个候选重复保护整个判定域。八卦阵、刚烈、洛神与延时锦囊也共用同一 `judge`，应由判定域声明统一的待决资格。

修复在 [judge](../src/rules/cards/judge.ts) 的两个待决窗口传入原有的纯 `active: live`。复用内核既有窗口收束机制，没有新增事件类型、全局技能开关或永久内核规则。

- 候选结束后若判定者死亡或已终局，本窗口不再执行剩余候选；不能进入下一改判窗口或计算新的匹配。
- 其他角色死亡不取消存活判定者的判定。内外层判定有各自闭包和处理区，内层仍有效时可以继续，只收束失效的外层。
- 已提交的翻牌、改判、材料交换和技能支付保留真实事实，不回滚。当前处理区余牌仍按既有清理规则处理。
- 结果封口前失效返回 `unavailable`、`matched: null`；仍保留原有 `judgment.finished` 结果事实、公共完成窗口及 `onResult` 调用契约。空判定同样不是伪造成功判定。

## 已完成结果不能倒改

`judgmentFinished` 是封口后的公共事实窗口，不属于待决改判资格。结果已经为 `judged` 后，完成后效导致判定者死亡或终局，不会将它倒改成 `unavailable`，其他公共观察者仍可看到该结果。

`onResult` 仍是普通作者后续函数。需要取得牌、造成伤害或执行其他动作时，作者检查结果和该动作的当前资格；不能把“历史判定成立”与“当前动作仍合法”混为一件事。标准技能已有自己的判断，既有来源效果和已宣告后续不会因本次修复被统一撤销。

单个候选中的 `ctx.abort` 仍只中止该候选的流程，由窗口主持继续处理其余候选，不自动取消整个判定。这是既有作用域契约，本批没有改写通用中止语义。

## 行为证据

[18 项新场景](../tests/scenarios/judgment-boundaries.test.ts) 分别覆盖两个待决窗口中的死亡/终局、其他角色死亡、已交换材料后失效、内层判定使外层失效、单候选局部中止、已封口结果，以及实际八卦阵响应中的死亡/终局。每项检查实体守恒、处理区和判定临时状态清理、决策关闭及事实重建。

首次报告 `.artifacts/validation/judgment-boundaries-before.json` 为 18 项中 14 项失败，其中两项误用回复参数、两项误判局部中止的范围，属于测试夹具问题。校正夹具但未修复实现时，`judgment-boundaries-before-corrected-fixtures.json` 为 12 项失败、6 项通过；这 12 项是待决窗口的实际缺口。修复后与既有判定、防具、魏将和谋士专项合跑，`judgment-boundaries-after.json` 的 102 项全部通过。

新增失效分支由规则场景证明。浏览器和 Windows 原生回归继续覆盖实际八卦、鬼才、洛神、刚烈等既有交互，不通过测试脚本注入死亡来冒充新分支的界面证据。完整验证与发布包结果见 [STATUS](STATUS.md)。

完整标准语义审计、复杂选择/额度、独立资源目录和完整离线验收仍需继续。本次修复不构成整个标准包的验收完成证明。

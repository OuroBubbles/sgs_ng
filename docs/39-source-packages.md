# 39 · 普通源码内容包

本批把标准内容与对局装配解开，并提供可运行的作者包入口。包仍是普通 TypeScript；不新增技能语言、沙箱或动态安装器。默认标准＋EX 保持 32 种牌、25 名武将、108 张实体牌，机制练习保持原来的 288 张牌序。

## 作者入口

在 `src/content/<packageId>/index.ts` 默认导出 `definePackage(...)`。构建入口 [available.ts](../src/content/available.ts) 用 Vite 的静态模块发现收集这些入口；新增包后重新构建，开局“扩展内容”中即可选择。当前客户端固定标准包作为基础，其他包默认关闭。运行中的牌局不会切换内容。

公开接口来自 [SDK](../src/sdk/index.ts)，实现见 [package.ts](../src/content/package.ts)：

| 字段           | 用途                                                                            |
| -------------- | ------------------------------------------------------------------------------- |
| `manifest`     | `id`、可读 `name`、内容 `version`、可选 `requires`                              |
| `cards`        | 普通卡牌定义，复用统一宣告、支付、目标、反制与结算                              |
| `skills`       | 技能列表，或接收本局 `CardBook` 的工厂                                          |
| `effects`      | 独立效果定义，普通触发/查询与数据，见 [56](56-independent-effects.md)           |
| `generals`     | 武将属性与技能 ID；可引用依赖包中的技能                                         |
| `decks`        | `id`、`label`、返回实体牌列表的普通 `create()` 函数                             |
| `cardViews`    | 卡牌 ID、显示类别与规则说明；名称仍从牌定义读取                                 |
| `generalViews` | 武将 ID 与静态立绘 URL，独立于规则状态，见 [57](57-portraits-content-images.md) |

包 ID 为小写字母开头的字母、数字、下划线或连字符。牌、技能、独立效果、武将、牌组和说明各自使用 `packageId:localId`，localId 遵循相同格式。不同内容类别可以复用同一个局部名字，同一类别不允许覆盖。

依赖的 `version` 若提供，按精确字符串比较；省略时只要求包存在。不提供版本范围解析或多版本择优。作者负责在规则内容改变时更新自己的版本声明。

## 两步装配与失败边界

`resolvePackages(available, selected)` 先验证声明、解析传递依赖并生成确定顺序：根选择和每层依赖按 ID 排序，依赖先于使用者，同一包只出现一次。重复包、重复声明、缺依赖、循环、版本冲突、越过自身命名空间的定义、引用未知牌的说明在这里报错。选中清单及版本数组为冻结快照。

`content.createBooks()` 为每局新建卡牌、技能、独立效果和武将目录。所有牌先进入真实 `CardBook`，再按依赖顺序登记各包效果并调用一次技能工厂，最后检查武将引用的技能。工厂返回的技能也检查命名空间和重复 ID；武将引用只允许自己或传递依赖中的技能，不能借用偶然同时勾选的其他包。效果只声明类型，不自动给角色添加实例；使用时由普通技能函数调用 book.effects.add/prepare。构建工具不参与这个过程，因此规则测试可以直接导入普通包模块。

技能与牌里的函数仍是受信任的普通代码，**不会静态分析闭包内部的所有引用**。技能工厂拿到整局目录，作者有责任为代码使用的其他包声明依赖。Window token 保留对象身份，不把含函数的定义深拷贝为数据。

`content.createDeck(id)` 只执行被选中的牌堆工厂，检查实体 ID 重复、牌名是否存在及是否属于自己或声明的依赖；最终实体数据与区域约束仍由 World 检查。未知牌堆直接报错，不自动换用标准牌堆。

[RoleMatch](../src/app/offline/role-match.ts) 完成这些目录、牌组与角色检查后才创建 Room。界面先成功构造下一局，才释放上一局；装配失败显示错误。每局开始在洗牌、授予技能和发牌之前提交 `match.content`，把有序 `{ id, version }` 清单写入 `content:selection` 状态。事实重建包含该声明；底层无包测试装配记录空清单，不冒充已锁定包版本。

这里锁定的是版本声明与本局目录，不是代码归档。没有保存源码、模块哈希或挂起函数，不能据此承诺跨代码版本恢复结算。开发时修改函数后重新构建并开始新局；不保证在挂起的技能中途热替换代码。

## 可运行的演武包

[workshop/index.ts](../src/content/workshop/index.ts) 从 SDK 和包内模块导入，最初精确依赖 `standard@0.1.6`，当前内容版本见 [STATUS](STATUS.md)，不导入标准包内部实现，也不为新牌增加内核分支；流程解包见 [40](40-flow-results-responses.md)，模式行动序见 [41](41-action-order.md)，技能身份审计见 [42](42-skill-identity-audit.md)，历史来源后效见 [43](43-retained-effects.md)，连环传播见 [45](45-chain-damage.md)，护盾与转移见 [46](46-shield-transfer.md)：

- 演武客：明确的虚构示例武将，自己的闻策与标准包武圣组合。
- 闻策：使用锦囊时可摸一张牌；通过当前 `CardBook` 判断牌类型，也能响应标准包锦囊。
- 整备：对自己使用的可反制锦囊，普通 `chooseOne` 在摸两张与回复一点之间选择；未受伤时只提供摸牌。
- 演武牌组：44 张实体牌，组合标准牌与 4 张整备，不改动标准牌堆。
- 遗玉与遗玉演练：40 张独立牌组，展示装备离场后的可选普通发动/摸牌，不使用专用 UI。
- 缚阵、引焰与连环演练：48 张独立牌组，展示公开连环、火焰传播及普通伤害函数；公共状态标记和基础 AI 同步支持。
- 凝障、守阵客/代受与护盾/转移演练：48 张独立牌组，展示公开护盾、费用提交时确定的转移意图与新的接收方防御；代受是自定义示例，不是完整天香。

勾选“作者演武”后可选演武客、守阵客与四种演武牌组，合计 37 种牌、27 名武将；取消后失效的武将和牌组自动回到基础选择，仍合法的选择保留。UI 使用包提供的牌面说明和实际目录名称，不维护第二份全局卡牌表。

复现：选择演武客、两人、AI 关羽、作者演武牌组、种子 `2`，开始对局；甲席首回合有整备。使用后发动闻策，再选择摸两张牌，可观察材料离手、净增两张手牌以及公开记录。闻策与整备继续使用现有技能说明、牌面详情和具名选项面板。

基础 AI 能处理这类通用选项、响应与已知标准动作，并已用启用扩展的对局完成胜负验证；对陌生牌的主动使用仍沿用现有基础评分，不声称理解任意作者代码的策略。高级策略和搜索继续后置。
